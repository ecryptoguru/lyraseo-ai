# Phase-one observation adapter fixture boundary

This package implements bounded format normalization and restricted **synthetic** collection rehearsal. It is not a provider transport, production-qualified collection, a provider billing reconciliation or an observation ingestion authority. The existing private `CONTROLLED_FIXTURE_V1` producer, artifact origin/checkpoint contracts and saved evidence remain unchanged.

Run `node scripts/test-observation-adapters.mjs` after installing dependencies and generating the local Prisma client. It creates a fresh uniquely named database on the existing PostgreSQL17 loopback service at127.0.0.1:54329, verifies the exact container/image/port, applies migrations, registers its owned fixture environment and runs only `tests/observation-adapters`. It never accesses the canonical test database, resets existing data, changes shared roles or restarts services. All databases are retained for review. Existing reviewed local ledger roles must already exist.

`fixtureObservationLedger` invokes migration34's atomic panel/version/prompt/profile-to-attempt binding. The ledger29 guard authenticates the restricted fixture login and independently registered database. Only a new database intent returns `submissionGranted:true`. Replay cannot submit; timeout does not trigger a replacement. Known-task polling can reconstruct its sealed handle from the durable binding and original accepted receipt after a process loses its in-memory handle. It never creates an attempt or reservation. Poll responses cannot turn the original POST charge into a refund. Unknown billing remains reserved. Charged refusals consume synthetic currency without a completed observation. Financial evidence can arrive after revocation; there is no source-persistence path.

Fixtures are constructed from an internal versioned catalog. Callers cannot supply arbitrary wire bytes, real credentials, endpoints or executable transport callbacks to this path. Pure normalizers accept bounded wire for format validation only; their output has no ingestion authority. Generated fixtures, fixture prices and sample location codes are explicitly synthetic. Public documentation examples are not operative tariffs. No code dispatches `fetch` or an SDK.

Current format references, inspected2026-11-03:

- [Azure Responsesv1](https://learn.microsoft.com/en-us/rest/api/microsoft-foundry/azureopenai/responses): response status, assistant output text/refusal annotations and usage. Hidden reasoning and retrieved search text are excluded.
- [Consumer ChatGPT Standard scraper](https://docs.dataforseo.com/v3/ai_optimization-chat_gpt-llm_scraper-task_get-advanced/): task envelope, requested data, returned model, markdown and source arrays.
- [Consumer Gemini Standard scraper](https://docs.dataforseo.com/v3/ai_optimization-gemini-llm_scraper-task_get-advanced/): separately pinned Gemini envelope and literal returned model label.

Only in-answer URL citation spans or the bounded inline-markdown-link subset establish annotations. Source/retrieved arrays do not. Unsupported markdown mapping is retained as unknown. Requested English/India is separate from returned language/location code; an unqualified numeric location code does not establish confirmed India. Account fingerprint is trusted context, not claimed proof in anonymous JSON. Schema drift, truncated/failed output and refusal never become measured absence. Consumer semantic refusal/completeness classification remains a bounded fixture contract; a live classifier/qualification must be independently established before live measurement.

## Structural live-source gate

Ledger29 intentionally restricts qualification classification to `SYNTHETIC|UNKNOWN|DOCUMENTED`, `live_enabled` tofalse, operation ledger mode to`LEGACY|FIXTURE`, attempt source namespace to`SYNTHETIC_LEDGER_V1` and cost provenance to`UNKNOWN|SYNTHETIC`. It cannot produce a qualified actual-provider operation or receipt. Existing private observation SQL accepts only `CONTROLLED_FIXTURE_V1`/synthetic manifests and has no current-operation binding for a real producer. Migration34 reports `PROVIDER_OBSERVATION_V1` unavailable and grants no artifact/source mutation privileges. Environment flags and qualification-shaped caller objects cannot bypass this.

The exact remaining interface is a separately approved qualified provider ledger mode with immutable account/profile/tariff/rights/exposure/executor admission; authenticated actual-provider financial facts; a versioned producer seal; and current-operation/profile/receipt/raw-rights/site/sponsor/session/proof/lease/pause/tombstone checks atomically repeated at source reservation/finalization using the existing origin/checkpoint machinery. That requires another reviewed contract; this fixture-only change deliberately does not invent qualification, broaden the private producer, or relabel provider wire as controlled fixture source.

The shared $10 ceiling, $8/$1/$1 partitions and25/100/100 allowances are unchanged. Synthetic fixture owners cannot mix new unmanaged admission into the same already-managed owner/month: ledger29 deliberately blocks runtime budget DML there. Tests use isolated synthetic sponsors, as the ledger suite does. This is not a claim of live per-user admission support.
