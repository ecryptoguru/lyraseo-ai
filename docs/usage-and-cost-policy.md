Limits are initial evaluation settings, not evidence that every task will succeed at those sizes.

Use the approved observation counters and internal currency reservations. Do not introduce editorial credits, research packs or helper counters as additional monthly entitlements. Cost reservations account for provider work, failures and retries. Check global, provider, workspace, per-site and job limits atomically before dispatch. A job needs both allowance and budget. Already committed provider requests may still incur charges after local cancellation or a budget alarm.

The scope/token/time bounds below are selected initial engineering defaults under the finalized engineering contract, subject to runtime evaluation. Dollar guards are unvalidated illustrations for complete logical jobs, including retries. They are not independent product price caps or additional founder decisions. Engineering should size a safe reservation from actual provider tariffs, task scope and remaining approved budget rather than reject a useful job solely because it exceeds an illustrative row value. Input/output token limits are per attempt and include system instructions, schemas and selected evidence. Output limits include billable reasoning plus visible output. Plain generation without tools has a calculable token ceiling at a pinned tariff. Azure web search has separate grounding/tool charges whose billing bounds must be verified, so its dollar guard is an admission/reconciliation policy, not a guaranteed provider-enforced hard cap. Verify supported tool-call limits, retrieval bounds and conservative reservations before release; disable paid observation admission if a safe bound cannot be established. Provider dashboard budgets alone are not an enforcement mechanism.

### 2.1 Retry and incomplete-output policy

Generation and Parallel jobs allow at most one retry per logical external operation, within the same reservation and logical deadline. A retry or one schema repair shares that allowance, never creates an extra unmetered generation stage, and is admitted only if its conservative maximum cost fits the remaining guard. This is a ceiling, not a requirement to retry every failure. Do not retry rejected inputs, permission denials or permanent source blocks. Backoff on transient throttling. One successful accepted observation is not repeated merely because it lacks a mention or citation.

If provider acceptance is uncertain, reconcile its request/task ID before replacement. For DataForSEO, resume polling a known task; delayed results are not a reason to submit a new paid task. If cancellation cannot stop a remote task, record the actual cost and do not promise an immediate vendor refund. Automatic high-reasoning escalation is disabled initially. Prompt/schema/config changes are versioned and need regression review.

Token-limit termination or a partial rewrite that fails the promised output contract is not a completed paid deliverable. Retain the draft visibly where helpful, mark it incomplete and do not mark the operation complete if no usable contracted output exists; internal spend remains recorded. A subsequent larger request needs new explicit scope/budget rather than silently billing repeated continuation calls.
