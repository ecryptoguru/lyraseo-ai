# Local legacy inline HTML transition

Migration `202611030014_legacy_inline_sources` is an additive, default-off local maintenance capability. It does not enroll any scope, fetch anything, contact providers, change financial records, or enable production deletion. Its scope label is `LOCAL_TEST_ONLY_ACTIVE_STORE`.

The executable separation is deliberately narrow: remove the independently stored `AuditPage.provenance.rawHtml` property after its original known `AuditPageRetention.rawExpiresAt` is due. Eligibility requires a terminal null-storage `readiness-v2` raw-profile run with no lease, the stored original capture clock validated against the provenance timestamp, a matching requested URL/manifest and the stored HTML UTF-8 SHA-256, a known provenance key contract, and bounded logical values. It preserves the complete evidence value, provenance remainder, original network SHA, all page/run identity and clocks, and the full evaluation. The format and storage markers never change.

`AuditPage.evidence` and the remaining provenance may still contain source representations or inseparable historical facts. They remain an explicit `AUDIT_PAGE_EVIDENCE_RESIDUAL` class. Historical evaluation diagnostics have no trustworthy field-level source lineage; the complete `AuditRun.evaluation` remains unchanged and classification-blocked. Historical `ContentDraft.snapshot` values likewise remain unchanged and classification-blocked. No snapshot is promoted to `saved-evidence-v2`, clipped, blanked, or given a replacement clock. Authored revisions, draft heads, and pins remain editable through their existing contracts. A transition receipt proves removal of its one specific HTML property, never completion of all source cleanup.

The SQL authority is the new NOLOGIN `lyraseo_legacy_inline_owner`; membership and privileged existing role state are rejected. It has only scoped API authority and narrow source-column write permission behind forced RLS. The existing restricted maintenance login can call `preview`, `make_plan`, `status`, `pause`, and `next`, but cannot inspect enrollment, alter content directly, assume the owner role, or edit receipts. Every operation verifies the supplied workspace/site, login, local test enrollment, database OID, postmaster start, PostgreSQL major and encoding before mutation. Enrollment itself requires the local administrator and locks Workspace then Site. There is no production enrollment helper or application GUC authority.

Enrollment fences old inline admissions, checkpoints, and finalizations under the same Workspace/Site locks. Existing private admission stays valid. Active legacy runs remain blocked; cleanup never converts them into terminal runs. Stale enrollment continues withholding unsafe reads and fencing old writers, while maintenance authority fails after a restart. Requalification after a restart is deliberately not provided by a maintenance bypass.

Product reads take shared Workspace then Site locks through response construction and their existing final actor/scope recheck. The original source double-read still compares bytes/digest/clocks after identity I/O. In an enrolled scope, raw legacy evaluations are omitted by the database query and returned as `null` with `legacy-lineage-withheld`; capture and comparison reject them. Legacy draft snapshots are withheld, while authored history, bodies, citations, and pin actions remain available. Other scopes and intentional `saved-evidence-v2` values retain their existing behavior. An already-delivered response cannot be recalled.

`next` locks Workspace FOR SHARE → Site FOR UPDATE → plan → page. The shared Workspace lock allows maintenance in unrelated sites to proceed. The plan lock and the common scope lock make pause a commit barrier in either race order. The candidate window is at most 50 page IDs; a stored cursor advances and wraps with a server-time 30-second backoff. Pending is not completion. Preview selects bounded ID windows, accepts a validated class/ID keyset cursor for inventory beyond 100 rows, and emits only opaque IDs, classes, statuses and the next cursor; it performs no writes. The bounded output may omit further items and never asserts that omitted items are clean.

Each transition inserts an append-only event and a private one-use permit in the same transaction, validates the exact monotone update in the immutable trigger, rereads the stored JSON, and checks complete protected facts. A deferred constraint trigger checks final stored JSON and fact fingerprints at transaction settlement. The hash domain is `P2B2_INLINE_PG17_UTF8_JSONB_TEXT_V1`, followed by a newline and the exact PostgreSQL 17 UTF-8 bytes of `jsonb::text`, SHA-256 encoded as lowercase hex. Old/new hashes cover `{evidence, provenance}`. The fact hash covers the complete page excluding provenance, the retained provenance, the complete audit row, and original capture row. These hashes differ from network SHA, private artifact fact hashes, and `saved-evidence-v2` identity. Receipts store domain policy, original IDs, class/field, lengths, deadline/source, transaction identity and database decision time; they store no source text.

Historical PostgreSQL TOAST values can decompress before a logical JSON size test. This implementation therefore makes no strict memory-bound claim. Operators must establish a real prior-statement server timeout, for example `BEGIN; SET LOCAL statement_timeout='3s'; SELECT lyraseo_legacy_inline.next(...); COMMIT;`. The gate tests a timeout while waiting on a real conflicting lock and verifies that no plan state survives rollback. The local-only profile does not justify running this on customer data, physical media, backups, or provider stores.

Run `node scripts/test-legacy-inline.mjs` on the existing validated PostgreSQL 17 loopback-only test container. It creates uniquely named databases from `template0`; it never opens or resets canonical fixture databases or changes existing cluster roles. It replays the original 27 migrations before populated additive replay, separately replays all 28 on an empty owned database, checks preview's zero-write snapshot, real restricted sessions, wrong scopes and guessed plans, direct mutation/role attacks, independent before/after hashes, protected facts and authored history, old-writer fencing/private admission, actual shared-reader contention, timeout rollback, pause in both orders, and server-time backoff. Five product API checks run only against the random owned database. Gate evidence is written under ignored `output/legacy-inline/run-<uuid>/gate.json`.

Remaining qualification includes a combined replay with the other phase-one migrations and their trigger exceptions, complete old checkpoint/finalization versus enrollment race matrix, a physical restart qualification, exact deadline-boundary timing, live authenticated application acceptance beyond component fixtures, and any future independently proven separation of the blocked residual classes. This is a qualified local HTML-property transition subset, not full legacy cleanup or phase-two erasure.


Final component verification additionally ran eight real Chromium checks on owned port 3026: desktop and mobile withheld draft/evaluation cases plus the existing normal draft/revision-conflict and current audit flows. The withheld draft test proves the missing snapshot does not crash, authored content/citations remain visible, and withheld internal links are not presented as known empty. Both surfaces passed axe and viewport checks, with screenshots under `output/playwright/legacy-*-withheld-*.png`. Two earlier test iterations failed on incorrect test assumptions (audit history button case/label, then collapsed receipt details); these assertions were corrected and the final eight-check run passed. Route tests reject a withheld CSV instead of returning a misleading empty export and provide stable private HTTP 409 error codes; MCP comparison errors provide the same structured category.

The final restricted gate checks direct column privileges as well as table privileges: maintenance has neither SELECT nor UPDATE on source provenance/snapshots, and the NOLOGIN owner has only draft identity/format columns (not draft snapshots). A synthetic stale enrollment fixture populated before creation of the INSERT guard proves that maintenance controls reject stale postmaster identity while product withholding and the writer fence remain active; private admission still succeeds. This synthetic fixture is explicitly not a physical restart test. A 153 row/class inventory test follows keyset continuation beyond 100 without duplication or writes.
