# Audit and measurement contracts

Version: 1.0 · Finalized for planning: 2026-10-23 · Methodology key: `readiness-v1`.

This is the engineering completion of the rule/measurement proposals in the [full-version specification](./full-version-spec.md). It does not claim implemented rules, validated ranking factors or live observations. Product budgets, phases and data lifecycles remain governed by their approved policies. [Engineering contracts](./engineering-contracts.md) own acquisition, auth and execution.

## 1. Inputs, normalization and evidence

Each rule consumes a bounded immutable PageEvidence record: requested/final normalized URL, acquisition outcome, original status/headers/body when available, rendered DOM, extracted main content, relevant robots groups, sitemap membership, observation timestamps and input hashes. Missing original HTML cannot be inferred from rendered DOM. Network failure, unsupported language/type, truncated input or uncertain applicability yields UNKNOWN for dependent checks. An observed 404 is known; a timeout is not a 404.

Text normalization: decode HTML entities, Unicode NFKC, collapse Unicode whitespace, trim. Main-content extraction chooses the single visible `main` or `[role=main]`; otherwise the largest visible `article`; otherwise body excluding script/style/template/noscript, navigation, header/footer and hidden/inert nodes. Ties use DOM order. Retain extraction strategy/version and bounded supporting excerpts. A rule needing computed visibility uses browser visibility evidence; missing it makes affected evidence unknown rather than assuming content is visible.

User-confirmed site facts: display brand name, verified exact origin, optional known aliases and organization URLs, intended indexing (default indexable with explicit confirmation), optional intended canonical per page, declared page type (marketing/article/product/other), optional required policy links. These are not model guesses. Page-type-specific checks lacking declaration are UNKNOWN or informational as stated below. User assertions are labelled declared facts, not independently verified truth.

Robots parser follows standards including specific user-agent groups, longest applicable path rule, allow on equal specificity, valid percent encoding and status semantics. 404 robots is no file; auth denial is not permission; 5xx/unreachable robots is unknown. HTTP X-Robots-Tag and initial/rendered meta directives retain source and agent. Google Search is the score profile; Bingbot/OAI-SearchBot/PerplexityBot and training-agent observations are separate. Never impersonate these agents to bypass a block.

RuleResult: `{ruleId,ruleVersion,scopeKey,outcome,priority,evidenceRefs,reasonCode}`. Outcomes PASS/WARNING/FAIL/UNKNOWN/NOT_APPLICABLE. Informational observations have no score weight. Scoring instances use weight1; category weights30/25/25/20. Severity/priority is separate from user review/disposition. Evidence includes exact observed value, source and acquisition time, bounded to512 normalized characters per finding excerpt; long source belongs in expiring private artifacts.

## 3. Score, coverage and comparison math

Freeze manifest before acquisition. Page instances use normalized requested URL keys; origin instances occur once. Redirecting two selected URLs to one destination retains both acquisition receipts but flags duplicate destination; it cannot silently remove a selected URL or alter the denominator. Informational observations never enter score or coverage.

For category c: `evaluatedWeight = PASS + WARNING + FAIL weights`; `unknownWeight = UNKNOWN weights`; `coverage = evaluatedWeight / (evaluatedWeight + unknownWeight)`. Proven N/A excluded. Category score = `(PASS weights + 0.5 * WARNING weights) / evaluatedWeight`. No evaluated weight with unknown applicability means no numeric category score. All instances N/A means category omitted.

Overall coverage uses category weights, so it aligns with scoring: sum(categoryWeight * categoryCoverage) / sum(activeCategoryWeights). Active means at least one evaluated or unknown instance. Overall score = round(100 * sum(categoryWeight * categoryScore) / sum(activeCategoryWeights)); round once, half up. Eligibility requires acquired homepage, at least80% manifest pages acquired as usable bounded HTML evidence, at least80% overall applicable-weight coverage and positive evaluated weight in each active category. If no active category exists, numeric score is null. Category weights renormalize only for all-N/A categories, never for an unknown category. Display per-category and total coverage.

Explicit non-indexable override: score0 only when every page in a fully acquired manifest has conclusive Google-search noindex and was declared intended indexable. It requires complete directive evidence, not robots disallow or external canonical. Findings and coverage remain visible. Otherwise use normal eligibility/math. A known error status may produce findings while preventing an eligible overall score through insufficient acquired-page coverage.

Comparison key `(ruleId,compatibleRuleVersion,scopeKey)`. FAIL/WARNING → PASS is resolved; new FAIL/WARNING after PASS is new; unchanged issue is persistent; removed page, UNKNOWN, changed scope or incompatible version is unevaluated. WARNING→FAIL is worsened; FAIL→WARNING is improved but unresolved. Dismiss/review/assignment never changes technical outcomes. Only same manifest/profile/methodology gives a headline score delta; other comparisons show overlapping evidence with explicit scope changes and no aggregate improvement claim.

## 4. Rule fixture matrix and reproducibility

Fixtures are local, synthetic/redacted and contain raw headers/body, rendered DOM/visibility, site declarations, manifest and expected rule results. No fixture test calls a provider. Every row above requires the named PASS/WARNING/FAIL cases where defined, plus missing-input and applicability cases. Store golden normalized output without timestamps/operation IDs; preserve provenance separately.

Mandatory named cases: `empty-title` (E02 FAIL/EMPTY_TITLE); `missing-title` (FAIL/MISSING_TITLE); `external-canonical-no-intent` (D03 WARNING); `canonical-declared-match` (PASS); `timeout-not-404` (D01 UNKNOWN); `observed-404` (D01 FAIL); `robots-disallow-no-noindex` (D04 WARNING, no override); `no-jsonld` (E05 N/A); `invalid-jsonld` (FAIL); `training-block-only` (informational); `article-type-unknown` (A04 UNKNOWN); `marketing-no-date` (A04 N/A); `empty-category` (no numeric score); `all-na-category` (weight renormalized); `partial-79-percent` (no score); `complete-noindex` (override0); `duplicate-final-url` (manifest unchanged); `removed-page-not-fixed` (unevaluated); `reviewed-not-fixed` (score unchanged).

Golden arithmetic: category scores1,0.5,0,1 with full coverage produce63 after half-up rounding of62.5. If entity category is all N/A, same remaining scores produce53 after rounding42.5/80*100. A category with 0 evaluated/positive unknown blocks the aggregate even if other categories pass. Mutating observation timestamp alone must not change normalized outcomes. Methodology changes create a new version; never recompute historical results silently.

## 5. Visibility unit, extraction and uncertainty

One logical observation is one prompt-version/surface-profile/locale/repetition response, sponsored by one product user. Profiles are Azure Sol API, DataForSEO consumer ChatGPT and DataForSEO consumer Gemini. English/India is the approved pilot target; record requested and provider-confirmed settings separately. Cohort key includes panel version, prompt set, source/provider/model version when exposed, retrieval mode, supported locale settings and extraction-version. An unknown consumer model is labelled provider-undisclosed; no invented model equivalence.

A valid complete answer with no mention is a successful zero. Transport failure, block, unsupported locale, missing/truncated answer or provider failure is unavailable and excluded from valid-response denominators. A refusal containing no substantive answer is `NO_ANSWER`, displayed separately and excluded; it may still carry provider cost. Retain expected slots, acquired valid slots and failure counts so low coverage cannot improve the apparent result silently.

Brand aliases are user-configured and versioned. Match normalized Unicode casefolded whole words/phrases in answer body, excluding source-list-only text; domains use parsed hostname equality or explicit owned subdomain relation, not substring matching (`brand.com.evil` never matches). Do not stem/fuzzy-match short names. Overlapping/ambiguous aliases enter review. Human adjudication records actor/version/reason and preserves original extraction.

Linked citation requires an actual answer annotation/reference with a source URL mapped to the brand domain; a provider's search-results/source array alone is not a citation. Recommendation requires an explicit suggestion to select/use the named product for the prompt intent. Plain mention, negative warning or unendorsed list is not automatically a recommendation. Use Luna only when interpretation is needed and budget fits, with an evidence span and confidence; otherwise unknown/review. A model's confidence never supplies missing evidence. No automatic Sol fallback for classification.

Per-brand extraction can be true/false/unknown. Unknown due to alias or recommendation ambiguity is not zero. Retain adjudicated evidence spans within the retention policy; no raw answer duplication in compact history.

## 6. Metrics and cohort comparisons

For brand b and metric m: denominator `D(b,m)` is valid complete answers in the selected cohort with determinate true/false extraction for that metric/brand. Numerator `N(b,m)` is true results. Rate = N/D; D=0 → null. Show `N / D`, valid answers, uncertain exclusions and unavailable observations. Mention, citation and recommendation each have their own denominator; never substitute the answer count when classification is unknown.

Competitor presence uses the same mention-rate formula for each configured brand. Rates may sum above100%. Share of voice is distinct: restrict to answers where mention states are determinate for ALL selected brands, count each brand once per answer, and compute `brand positive slots / all selected-brand positive slots`. No-brand answers add zero to both but their count is displayed. If all answers have no brand, SOV is null, not0 or100. Changing the selected competitor set changes SOV's denominator and prevents direct historical comparison unless recomputed from retained compatible evidence under the same set.

Default weighting: equal prompt weight. Within a prompt, average its valid determinate repetitions; average prompt rates across the common eligible prompt set. Show prompt and answer coverage; missing prompts are not zero. Publish raw pooled N/D separately and label it pooled, because uneven repetitions can otherwise dominate. Cross-engine results remain separate; no combined headline score. Portfolio overview lists site results and, when requested, an explicitly labelled equal-site descriptive average only across the same profile/period/metric with nonnull values; expose included/excluded sites, never portray it as market share.

Trend comparison requires same panel/extraction/profile/brand-set and locale settings, same window duration and common prompt IDs. At least10 common prompts with determinate results and at least80% planned-slot coverage in BOTH windows are needed for an aggregate descriptive delta. Show numerator/denominator and percentage-point change, not statistical significance, causation or market-wide growth. Below this threshold show individual observations and “Insufficient comparable evidence.” Changed model/profile starts a new cohort; no silently bridged trend. The25 API allowance does not itself guarantee two qualifying windows.

Metric fixtures: two valid answers and one unavailable, brand mentioned once →50% with failure shown; valid no-brand answer →0%; ambiguous alias excluded and shown uncertain; source-list URL without annotation →no linked citation; brands A in2 answers/B in1 answer →SOV A2/3, B1/3, even if overlapping; all no-brand →null SOV; mismatched competitor set →no headline SOV delta; unequal repetitions distinguish pooled versus equal-prompt rate; insufficient common prompts →no aggregate trend; no raw-answer rights →unsupported evidence contract, never fabricated response.

## 7. Acceptance

Pure rules and metric functions accept immutable typed inputs and return normalized results with no network/clock/random dependency. Inject current time only into expiry/access checks outside scoring. Test golden cases, property invariants (UNKNOWN cannot become PASS, no value outside0–100, identical snapshots deterministic), and adversarial URL/alias strings. Human review of the authorized fixture corpus evaluates false positives and useful guidance before real-user release; published weights/heuristics are versioned product choices, not validated search-engine ranking factors.
