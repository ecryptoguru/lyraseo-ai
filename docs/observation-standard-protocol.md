# Consumer observation protocol rehearsal

The consumer observation adapter contains a local, network-free rehearsal of DataForSEO's Standard ChatGPT and Gemini task protocol. It prepares one normal-priority task at a time, with an English language code, explicit location code and immutable correlation tag. Provider documentation describes the [ChatGPT task endpoint](https://docs.dataforseo.com/v3/ai_optimization/chat_gpt/llm_scraper/task_post/) and [Gemini task endpoint](https://docs.dataforseo.com/v3/ai_optimization-gemini-llm_scraper-task_post/). The 2,000-character task limit, priority and URL-encoding requirements were checked against those pages; account access, market support, rights and tariffs have not been qualified.

A successful creation receipt must bind exactly one accepted task to its original surface, prompt, tag, language and location. The adapter accepts only a bounded response with an unambiguous task ID, and retains a provider-reported decimal cost only when it can be represented exactly. If the task was accepted but cost is missing or unrepresentable, the task remains known and its cost remains unknown. Malformed, oversized, inconsistent, duplicated or failed receipts require reconciliation and do not authorize resubmission. The fixture ledger records a synthetic acceptance or uncertainty before any polling; a poll does not post a replacement.

The bounded result normalizers also reject duplicate JSON members instead of choosing the last value. Only a numeric JSON token can supply a provider-reported decimal; a provider object or array that resembles an internal marker remains an unknown cost. A duplicate result is unavailable rather than a measured absence or a reported charge.

This protocol code has no network transport, credentials, customer execution authority or paid dispatch. The fixture responses and ledger are explicitly synthetic. The customer visibility-run API remains unavailable until a qualified account, bounded provider spend, durable provider receipt and reconciliation, authorized execution principal, private source producer, raw-answer rights and supported market are independently implemented and verified. Azure API and the two consumer surfaces remain separate measurements.

An authorized site editor can preview a reviewed panel and one surface without starting an operation. The preview reports current site-verification status, the number of questions, connector length conflicts and a timestamped snapshot of that user's UTC-month combined, provider and surface allowances. It deliberately returns no quote or maximum cost while the provider is unqualified, and reports that saved-result reuse was not checked. The snapshot is informative only: a future admission must issue a fresh server quote, reauthorize the user and reserve the correct partitions atomically.
